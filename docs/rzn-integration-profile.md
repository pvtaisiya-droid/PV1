Дата анализа: 10.11.2026. Рабочая ветка `codex/rzn-as2-foundation`, исходный SHA `c80347d42c2a8cb516aeab3eba384df1967df0f6` (`share/pv1-20261030`).

Карта не является формальным контрактом сериализации или заявлением о conformant XML. В ICH присутствуют блоки, применимые по обстоятельствам: литература C.4, исследование C.5, смерть D.9, родитель D.10, анализы F, анамнез D.7/D.8. Они не исключены целиком. Их неприменимость устанавливается для конкретного случая по фактам, не по отсутствию полей PV1. Иные расширения ISO/HL7 (например ветеринарные/устройств) не включены: задача — ICSR лекарственных препаратов, а региональное расширение для них не предоставлено.

Аналитическая карта использует определения International Council for Harmonisation (ICH), переработанные для сопоставления с PV1; это не официальный документ ICH и не одобрено ICH/РЗН. Источники I2–I5 и места приведены в каждой строке.

## 5. Сообщения из клинических исследований

**Что подтверждено:** общий ICH содержит идентификацию исследования C.5, тип сообщения C.1.3, признак ослеплённого исследуемого продукта G.k.2.5 и идентификацию участника D.1.1.4. C.5.4 условно требуется для сообщения из исследования (I2 §C.5.4, PDF с.72). Это формат передачи, а не самостоятельное правило, какие НЯ следует представлять.

**Что не подтверждено:** ни название объединённой подсистемы в R1, ни возможность закодировать исследование в R3 не доказывают приём любого сообщения КИ через рассматриваемый шлюз. R1 P2 описывает направление из баз держателей РУ в «Фармаконадзор 2.0»; публичные FAQ R6 описывают «МКИЛС» и отдельные ситуации по территории исследования. Из этих материалов нельзя вывести универсальный AS2-маршрут для КИ. Нужны актуальное письменное разъяснение/инструкция и тестовый принимаемый пример по каждой согласованной категории Q08.

Необходимо хранить раздельно (проектное решение S2-06):

| Объект решения / данные | Связь с ICH и PV1 | Что уточнить у ответственного ФН / РЗН |
|---|---|---|
| Факт события, дата, исход; критерии серьёзности по каждой реакции | E.i; Reaction частично есть | Подтвердить источник и оценку, не выводить «серьёзное» из интенсивности события. |
| Причинная связь каждой пары препарат–реакция, оценки исследователя и спонсора | G.k.9.i.2.r; CaseProductReactionAssessment частично есть | Как передавать расхождение оценок; роль препарата сравнения и не исследуемой сопутствующей терапии. |

До Q08 допустимо проектировать перечисленные поля и фиксировать ручное решение ответственного ФН. Нельзя автоматически назначать статус «подлежит AS2-передаче» по `is_serious=True`, по `expectedness` или только по `C.1.3=2`. Сроки и юридические правила представления здесь не назначены: их актуальное документальное основание отсутствует.

## 6. Единый перечень недостающих оснований

Не нужны пароли от АИС. Пользователь/уполномоченный сотрудник получает выгрузки из своей АИС; обращения от его имени в этом этапе не отправлялись. Непредоставленный документ не объявляется существующим: если отдельной спецификации нет, нужен официальный ответ с альтернативным источником правила.
