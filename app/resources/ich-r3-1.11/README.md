# Pinned local ICH profile

`ich-r3-1.11-pv1-local-1` is a PV1 **local** profile, not an approved RZN profile.

Source: [official ICH complete package 1.11](https://admin.ich.org/sites/default/files/inline-files/IG_Complete_Package_v1_11_1.zip).
Archive SHA-256: `a3e3f4e2fbec61abec6a3166cb96cc8236f496b08554f71ff661e4ae8172ff72`.
Implementation Guide 5.03 and Appendix I(G) 1.03, 18 July 2025; reference instance 3.1.

The 50 XSD files (923,289 bytes) are the dependency closure of
`4_ICH_ICSR_Schema_Files/multicacheschemas/MCCI_IN200100UV01.xsd`.
They were copied **byte-for-byte**; their original notices are retained. No simplified/repaired schemas.
Runtime entry: `xsd/multicacheschemas/MCCI_IN200100UV01.xsd`.
`manifest.json` lists every file hash, package/source/version, exporter and rule versions.
Its SHA-256 is pinned in `app/r3_profile.py`; the resolver rejects other paths and network URLs.
Runtime needs neither the original temporary download nor network access.

`layout.json` is PV1 structural metadata, not an official schema. It records reviewed
namespace paths, child ordering, HL7 structural attributes, fixed concept codes/OIDs,
and individual snapshot-field recipes. It contains no clinical sample values.
`tools/build_r3_layout.py <extracted-package-directory>` reproducibly extracts it from
`5_Reference Instances/00_ICH_ICSR_Reference_Instance_variation_v3_1.xml` and
`app/clinical_contract.json`. The reference SHA-256 is
`ef55d8c7c7948d2cb77b35ab72aa1e1e09ca8a384023f7a82bedc25d24662952` and is checked by that tool.
The E.i.6 width recipe uses the confirmed IVL_TS width representation; the first reference
reaction does not itself contain width. F.r.3.4 selects ED explicitly. No XSD is altered.
Updating a recipe requires review, a new profile/rule version as appropriate, and new
layout/manifest hashes; regeneration is a development operation, never runtime auto-discovery.

Local limits: snapshot 20 MiB / 10,000 records; one document 8 MiB; XML 32 MiB.
DTD/entities/network are disabled; only trusted includes/imports are resolved.
XSD does not verify MedDRA membership, all ICH conditional business rules, clinical
reportability, or acceptance by a recipient. Those results remain separate.

Synthetic examples are generated by `tests/r3_export_helpers.py`, not copied from incoming
XML. Their people, products, study IDs and MedDRA codes are invented. Tests assert both
official-XSD validity and independent expected XPath values/links.
